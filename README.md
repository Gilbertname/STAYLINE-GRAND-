# STAYLINE GRAND 2.5 — 原版介面 Vercel 無登入展示版

## 本版特色

保留 **STAYLINE GRAND 2.5 原始 UI**，使用原有 `index.html`、`styles.css`、`app.js`、`ops.js`、`guest.html`、`guest.css`、`guest.js`、房型照片，以及學生審核頁。新增 `demo-api.js`，在瀏覽器中模擬原來的 Python API；沒有 Python 後端，也不需要登入。

- 管理後台：首頁 `/`。原始深藍側邊欄、營運總覽、訂房、房務、房客、收款、報表、員工、排班請假、培訓、薪資、客房服務、客服、入住退房申請與打卡。
- 顧客網站：`/guest`（亦可 `/guest.html`）。原有風格與房型照片、選日期、建立模擬訂單、預計抵達時間、學生九折、結帳。
- 學生優惠審核：`/student-review`（亦可 `/student-review.html`）。模擬核准或拒絕，僅標準客房適用學生九折。
- 入住時間 15:00 起、退房 11:00 前。
- 無帳號與登入、無伺服器、無真實付款、無真實身分驗證、無伺服器資料庫。

## 部署 Vercel（建議以新專案部署）

1. 將此資料夾裡的內容（包含 `index.html`、`demo-api.js`、`vercel.json` 及 `room-images/`）上傳到**新的** GitHub Repository 根目錄。不要只上傳外面包著資料夾的 ZIP。
2. 到 Vercel → **Add New / Project** → 匯入這個 Repository。
3. **Framework Preset: Other**。Root Directory 設定為實際包含 `index.html` 的目錄（一般為 `./`），**Build Command 留空**。
4. 部署後打開根網址；驗證 `/guest` 和 `/student-review` 也可以開啟。
5. 在顧客端下單並切到後台的學生審核頁進行測試。

也可使用 Vercel Drop 上傳「本資料夾的內容」；部署後請先確認 `https://你的網址/demo-api.js`、`/styles.css` 和 `/guest.css` 不會出現 404。

> `server.py`、`hotel_modules.py`、`checkout25.py`、`*.db`、`__pycache__` 與測試 Python 檔不需要部署，此示範版沒有使用它們。不要上傳真實顧客、員工、學生證資料。

## 如何測試整條流程

1. 打開 `/guest`。直接以**虛構展示旅客**進入，免登入。
2. 選擇標準客房及有效入住日期，按「預訂」，勾選學生九折並填入**虛構學生資料**。
3. 顧客結帳頁應顯示待審核，不允許按學生價模擬付款。
4. 打開 `/student-review`，核准該筆**模擬審核**。
5. 回顧客結帳頁（切回分頁後會重新讀取資料）／回我的訂單，進行模擬信用卡或轉帳付款；不需也不應輸入真實卡號。
6. 返回 `/` 的「訂房管理」、「收款紀錄」及「營運報表」查看結果。
7. 在「排班與請假」新增、編輯班次，驗證編輯保存。
8. 若要重新演示，管理後台右上角按「重設展示資料」。

## 模擬資料保存範圍與限制

- 使用瀏覽器 `localStorage` 保存資料：**同一個瀏覽器、同一個網址的分頁共用**。其他訪客、裝置或瀏覽器無法看到你的模擬紀錄。
- 資料會留在該瀏覽器，直到清除網站資料或按「重設展示資料」。**不是雲端持久化資料庫，也不保證不丟失資料**。
- 公開網址沒有權限控制；任何人都可在自己的瀏覽器模擬管理員動作。只適合資工系專題公開展示。
- 學生審核是模擬狀態切換，無法檢驗真正的學生證。請勿輸入真實個資。
- 模擬金流不會扣款，不收集信用卡資料。
- 這份版型保留原 2.5 UI，但後端行為是瀏覽器模擬，不是原 Python + SQLite 的一比一雲端遷移。部分資料驗證和正式資料交易能力不等同原版。

## 舊系統不受影響

你原本在 Windows 使用的 `STAYLINE GRAND 2.5` 及 `stayline_grand.db` 無需刪除；這是新的一份獨立作品展示專案。
